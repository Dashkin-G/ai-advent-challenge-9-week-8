# Новый эндпоинт

1. **Где логика.** Найди модуль фичи (`rag.py`, `support.py`, `files.py`…). Логику пиши там функцией модуля;
   новый модуль — только для новой фичи, по шаблону из `CLAUDE.md`.
2. **Настройки.** Числа и пути, которые захочется поменять, — в `app/config.py` через `os.getenv` с дефолтом и
   комментарием «зачем».
3. **Маршрут в `app/main.py`.** Тонкий: разобрать вход (Pydantic-модель для тела, параметры — аргументами
   функции), пустой или неверный вход — `HTTPException(status_code=400, detail="<что написать>")`, вызов модуля.
   Долгая работа по шагам — поток событий NDJSON через `assistant.dumps`, короткая — обычный dict.
4. **Ошибки.** `llm.LLMError` и ошибки MCP показываются пользователю словами, не трассировкой: без потока —
   503, в потоке — событие `error`. Ошибки валидации параметров — по-русски, через обработчик в `main.py`.
5. **Проверка** — `ruff`, импорт и вызов эндпоинта через `TestClient` с заглушкой векторов (раздел «Проверка»
   в `CLAUDE.md`): удачный ответ и каждая ошибка. Агент `style-reviewer` — только если правка крупная
   (раздел «Субагенты и скиллы»).
