## День 36. Rules: файл правил проекта

Для проекта написан `CLAUDE.md` — правила, по которым Claude Code пишет код: стек, структура и слои, имена,
примеры хорошего кода, запреты, шаблон модуля. Рядом — локальный конфиг, скилл и субагент. Правила проверены
боевой задачей: один промпт без уточнений → оценка → правки правил → тот же промпт ещё раз.

### Как работает

```
правила проекта                        CLAUDE.md · .claude/settings.json · .claude/skills · .claude/agents
  + глобальный конфиг                  ~/.claude/CLAUDE.md
        │
experiment/generate.ps1 <имя> [-Rules v1]
  ├─ копия проекта в %TEMP%\claude-rules\<имя> с выбранными правилами
  ├─ claude -p < experiment/prompt.md  — один промпт, без человека
  │     Claude Code на qwen3.5-plus (Anthropic-совместимый адрес DashScope) или на Claude по подписке
  └─ experiment\<имя>\: правила генерации, log.jsonl, changes.diff, checks.txt, result.md
        checks.txt — ruff, импорт и одинаковые 7 запросов к новому эндпоинту без Ollama (smoke.py)
```

- **Боевая задача** (`experiment/prompt.md`): `GET /api/search` — поиск по документации без модели,
  параметры `q` и `top` (не больше 10), в ответе фрагменты и время поиска.
- **Копия вне проекта** — чтобы к правилам генерации не подмешался `CLAUDE.md` из папок выше и чтобы
  репозиторий не менялся.
- **Модель генераций — Qwen**, как и у агентов курса: на слабой модели видно, что правила дают, а Opus многое
  угадывает по коду и сам. Opus по подписке прогнан один раз — для сравнения.

### Что в правилах

| Файл | Что там |
|---|---|
| `CLAUDE.md` | стек, структура и слои, соглашения, 5 примеров из кода проекта, 6 запретов, шаблон модуля, README, проверка, когда звать субагента |
| `.claude/settings.json` | локальный конфиг: разрешены `ruff`, `python` из `.venv`, `git status/diff` |
| `.claude/skills/new-endpoint` | скилл: порядок работы над эндпоинтом — настройка → модуль → маршрут → ошибки → проверка |
| `.claude/agents/style-reviewer.md` | субагент: сверяет diff с `CLAUDE.md`, запускает проверки, код не правит |
| `ruff.toml` | линтер под стиль проекта: код недели 7 проходит чисто |
| `experiment/rules/v1/` | первая версия всех правил — для повторной генерации |

### Запуск

```
.\experiment\generate.ps1 qwen-v1 -Rules v1      # правила v1
.\experiment\generate.ps1 qwen-v2                # текущие правила (v2)
.\experiment\generate.ps1 opus-v2 -Provider claude   # Claude Code по подписке
```

Ключ `DASHSCOPE_API_KEY` — из переменной окружения или `.env`. Переменные Qwen скрипт ставит только на время
прогона: обычный Claude Code в том же окне и в других проектах работает по подписке.

### Как проверить задание

- **Файл правил v2** — `CLAUDE.md`, скилл, субагент и конфиг в корне; v1 — `experiment/rules/v1/`.
- **Диффы двух генераций** — `experiment/qwen-v1/changes.diff` и `experiment/qwen-v2/changes.diff`; у каждой —
  `result.md` (ответ, время, ходы, токены, инструменты) и `checks.txt` (линтер, импорт, ответы эндпоинта).
- **Что повлияло на качество** — «Находки».

Изменения правил v1 → v2 — по разбору генерации opus-v1:
- «Соглашения»: эндпоинт без потока — 400 на неверный вход, 503 без Ollama; ошибки валидации по-русски через
  один обработчик `RequestValidationError`; «сначала найди готовое» — opus-v1 завёл `find` рядом с `search`;
- «Проверка»: команда — отдельным вызовом, пути относительные через `/`; рецепт вызова эндпоинта без Ollama —
  `TestClient` без lifespan, векторы заглушкой, кэш во временной папке;
- «Субагенты и скиллы»: `style-reviewer` — только после нового модуля или правок больше чем в трёх файлах;
- скилл — коды ошибок и проверка через `TestClient`; конфиг — разрешения под Bash.

### Находки

- **Рецепт с готовой командой выполняется, правило в списке — нет.** Qwen с v2 скопировал заглушку из
  «Проверки» и вызвал свой эндпоинт. Но 503 и обработчик валидации из «Соглашений» не сделал: английский 422
  увидел в своём же тесте и записал в отчёт как норму. Правило, которое нужно применить, лучше давать
  критерием готовности в скилле, а не строкой среди двадцати.
- **Больше всего на процесс повлиял раздел «Проверка».** v1 склеивала команды через `;`, разрешения были
  записаны с `\` для PowerShell — в `claude -p` спросить некого, и проверки падали: у Opus 5 отказов, у Qwen 8.
  Opus отдал проверки субагенту, Qwen — сдал код с ошибкой линтера. С «отдельным вызовом, пути через `/`» —
  2 ошибки, обе от запуска сервера, о котором не просили.
- **Субагент на мелкую правку — лишние минуты.** Правило «`style-reviewer` — только для крупных правок»
  сократило Qwen со 180 до 82 с без потери проверок.
- **Глобальный конфиг тоже влияет.** Qwen с v1 вместо скилла проекта взял `code-review` из глобальных плагинов.
  Около 400 тыс. входных токенов почти не зависят от правил: это системный промпт Claude Code и плагины.
- **Opus угадывает то, чего нет в правилах:** 503 без Ollama, 400 по-русски на пустой `q`. Qwen без явного
  правила делает как в типовом FastAPI. Поэтому правила проверяли на Qwen.
- **Настройки проекта в незнакомой папке не действуют**: «workspace has not been trusted» — разрешения из
  `.claude/settings.json` скрипт передаёт флагом `--allowedTools`.
- **DashScope не кэширует промпт** в Anthropic-режиме (`cache_read_input_tokens: 0`): каждый ход заново
  оплачивает весь контекст.

## День 37. Профили агентного режима: Bug Fix, Research, «Перед коммитом»

Три профиля Claude Code: системный промпт, набор инструментов, что профиль должен и не должен делать, формат
ответа. Профиль включается на всю сессию — `claude --agent bug-fix`. Каждый проверен на реальной задаче одним
промптом без человека на `qwen3.5-122b-a10b` (DashScope); не сработал — профиль доработан и прогнан снова.

### Как работает

```
.claude/agents/<профиль>.md          frontmatter: имя, описание, инструменты · тело — системный промпт
        │
claude --agent <профиль>             промпт профиля заменяет системный промпт Claude Code, инструменты — только
        │                              из списка; CLAUDE.md проекта и глобальный остаются в контексте
experiment/generate.ps1 <имя> -Agent <профиль> [-Clone]
  ├─ копия проекта в %TEMP%\claude-rules\<имя>; -Clone — с историей git и незакоммиченными правками
  ├─ claude -p --agent <профиль> < experiment/tasks/<профиль>.md
  └─ experiment\<имя>\: профиль, log.jsonl, changes.diff, checks.txt, result.md
        checks.txt — ruff, импорт, файлы, которые изменил агент, и проверка задачи experiment/tasks/<профиль>.py
```

### Профили

- **`bug-fix`** — Read, Grep, Glob, Edit, Bash; без Write — временных файлов не остаётся. Должен: воспроизвести баг
  до правки и той же командой после, найти строку-причину и все задетые места, прогнать ruff и импорт. Не должен:
  чинить симптом (`try/except`), трогать лишнее, объявлять «исправлено» без повторного воспроизведения, коммитить.
  Ответ: что нашёл → что починил → что проверил (таблица) → что не проверено.
- **`research`** — Read, Grep, Glob, Bash; без Edit и Write — менять файлы нечем. Должен: первым вызовом — карта
  входов, каждое утверждение — `файл:строка`, прочитанная в этой сессии, отсутствие — прямо («авторизации нет»).
  Не должен: менять файлы, утверждать без места в коде, чинить. Ответ: коротко → файлы → связи (схема) → выводы →
  где искал.
- **`commit-check`** — Read, Grep, Glob, Bash. Должен: проверить всё, что уйдёт в `git add -A`, — секреты, адреса и
  почту, лишние файлы, следы ИИ, ruff и импорт. Не должен: менять файлы и индекс, показывать секрет целиком, писать
  «чисто» без поиска. Ответ: вердикт → что войдёт → таблица проверок → что исправить → команда коммита.

Общее: какие команды проходят без подтверждения (в `claude -p` спросить некого); у Bug Fix и Research ещё —
настройки через `os.environ` внутри `python -c` и вывод Python в UTF-8.

### Запуск

```
claude --agent research                                    # сессия в профиле; так же bug-fix и commit-check
.\experiment\generate.ps1 bug-fix-v1 -Agent bug-fix -Model qwen3.5-122b-a10b
.\experiment\generate.ps1 research-v3 -Agent research -Model qwen3.5-122b-a10b
.\experiment\generate.ps1 commit-check-v1 -Agent commit-check -Clone -Model qwen3.5-122b-a10b
```

В обычной сессии профиль работает и как субагент: «проверь перед коммитом» → `commit-check`.

### Задачи

- **Bug Fix** — настоящий баг: с `HOST=0.0.0.0` (открыть ассистента с другого устройства) в шапке ветка «?»,
  `/help` падает на шаге MCP: «Server returned an error response». Профиль получил только симптом —
  `experiment/tasks/bug-fix.md`. Причина — `app/config.py`: адреса MCP собирались из `HOST`, к `0.0.0.0` подключиться
  нельзя, запрос уходит в системный прокси и получает 503. Проверка стенда — `experiment/tasks/bug-fix.py`: сервер с
  `HOST=0.0.0.0` и с `127.0.0.1`, все три MCP-сервера.
- **Research** — «Как у нас устроена авторизация? Кто может пользоваться ассистентом и его MCP-серверами и что
  через них можно сделать?». Верный ответ: авторизации нет, защита — только `HOST=127.0.0.1`.
- **«Перед коммитом»** — настоящий коммит дня 37.

### Как проверить задание

- **Профили** — `.claude/agents/bug-fix.md`, `research.md`, `commit-check.md`.
- **Успешные прогоны** — `experiment/bug-fix-v1/`, `research-v3/`, `commit-check-v1/`: `result.md` (ответ, время,
  ходы, токены), `checks.txt`, `log.jsonl`, `changes.diff` — если агент менял файлы; профиль, с которым шёл прогон, —
  в `.claude/agents/`.
- **Что доработано после первой попытки** — неудачные `experiment/research-v1/`, `research-v2/` и список ниже.
- **Фикс бага** — `app/config.py`: из `experiment/bug-fix-v1/changes.diff`, исправлена опечатка в комментарии.

Research и «Перед коммитом» не изменили ни одного файла — по снимку копии до и после прогона. Вердикт «Перед
коммитом» перепроверен отдельным поиском по всем 113 файлам репозитория после коммита: ключа DashScope, ключей

Что доработано:
- **До первого прогона** — по замерам на 5–12 тыс. токенов. Команду `HOST=… python …` разрешения не пропускают, а
  Qwen после отказа останавливается → настройки — через `os.environ` внутри `python -c`, отклонённую команду —
  заменить разрешённой. MCP приложение вызывает по HTTP у себя же, `TestClient` этого не покажет → готовый рецепт
  «сервер с настройками и запрос к нему». Русский лог Python приходит кракозябрами → вывод в UTF-8. Логи прогонов
  по 200 КБ → «Перед коммитом» ищет по ним, а не читает.
- **Research v1 → v2**: «отвечаешь только прочитанным», «первое действие — вызов инструмента», критерий «Готово,
  когда». Не помогло — снова один ход без инструментов.
- **Research v2 → v3**: первый вызов задан готовым — Grep карты входов `@app\.(get|post)|app\.mount|__main__`; в конце
  промпта — «первым сообщением только вызовы инструментов». Сработало.
- **Bug Fix** и **«Перед коммитом»** сработали с первого раза и не дорабатывались. У «Перед коммитом» на будущее:
  искать всё сразу и не читать новые файлы целиком (отсюда 32 хода и 604 тыс. токенов), почта — отдельной строкой,
  число файлов — командой, а не на глаз.

### Находки

- **На вопрос Qwen отвечает из головы, на задачу — работает.** Research v1 и v2: один ход, ни одного вызова,
  «Где искал» с выдуманными запросами. В размышлении модель пишет «нужно найти код в main.py» — и сразу выдаёт ответ.
  Bug Fix в тех же условиях сделал 16 вызовов.
- **Правило не исполняется, готовый первый шаг — исполняется.** «Первое действие — вызов инструмента» не помогло,
  конкретный Grep с шаблоном — помог. Тот же вывод, что в дне 36: рецепт с командой работает, правило — нет.
- **Профиль втрое дешевле на старте, но не за прогон.** С `--agent` нет системного промпта Claude Code и лишних
  инструментов: первый запрос — 9 тыс. токенов против 25,7 тыс. в дне 36. Дальше контекст растёт от вывода команд и
  прочитанных файлов, а DashScope не кэширует: Bug Fix за 17 ходов потратил 342 тыс.
- **Запрет инструментом надёжнее запрета словами.** У Research нет Edit и Write — менять файлы ему нечем.
- **Запрет конвейеров в профилях строже, чем нужно.** Команды чтения в конвейере (`git grep … | head`, `sort`, `wc`)
  Claude Code пропускает сам; не проходят префикс `VAR=…` и абсолютный путь к программе.
- **Подсказка «адрес и код ответа — в логе» сработала**: причину Bug Fix нашёл по строке
  `POST http://0.0.0.0:8799/mcp/git/ … 503`.
- **Слабые места Bug Fix** — это и есть его 2 ошибки: свой бесконечный цикл (`iter(lambda: r.iter_lines(), None)`)
  выдал 5 ГБ вывода — Claude Code остановил его сам; абсолютный путь к Python отклонён. В отчёте «не проверено: —»,
  хотя страницу файлов агент не вызывал; её проверил стенд.
