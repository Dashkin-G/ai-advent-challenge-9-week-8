## День 36. Rules: файл правил проекта

Для проекта написан `CLAUDE.md` — правила, по которым Claude Code пишет код: стек, структура и слои, имена,
примеры хорошего кода, запреты, шаблон модуля. Рядом — локальный конфиг, скилл и субагент. Правила проверены
боевой задачей: один промпт без уточнений → оценка → правки правил → тот же промпт ещё раз.

### Как работает

```
правила проекта                        CLAUDE.md · .claude/settings.json · .claude/skills · .claude/agents
  + глобальный конфиг                  ~/.claude/CLAUDE.md
        │
experiment/generate.ps1 <имя> [-Rules v1]
  ├─ копия проекта в %TEMP%\claude-rules\<имя> с выбранными правилами
  ├─ claude -p < experiment/prompt.md  — один промпт, без человека
  │     Claude Code на qwen3.5-plus (Anthropic-совместимый адрес DashScope) или на Claude по подписке
  └─ experiment\<имя>\: правила генерации, log.jsonl, changes.diff, checks.txt, result.md
        checks.txt — ruff, импорт и одинаковые 7 запросов к новому эндпоинту без Ollama (smoke.py)
```

- **Боевая задача** (`experiment/prompt.md`): `GET /api/search` — поиск по документации без модели,
  параметры `q` и `top` (не больше 10), в ответе фрагменты и время поиска.
- **Копия вне проекта** — чтобы к правилам генерации не подмешался `CLAUDE.md` из папок выше и чтобы
  репозиторий не менялся.
- **Модель генераций — Qwen**, как и у агентов курса: на слабой модели видно, что правила дают, а Opus многое
  угадывает по коду и сам. Opus по подписке прогнан один раз — для сравнения.

### Что в правилах

| Файл | Что там |
|---|---|
| `CLAUDE.md` | стек, структура и слои, соглашения, 5 примеров из кода проекта, 6 запретов, шаблон модуля, README, проверка, когда звать субагента |
| `.claude/settings.json` | локальный конфиг: разрешены `ruff`, `python` из `.venv`, `git status/diff` |
| `.claude/skills/new-endpoint` | скилл: порядок работы над эндпоинтом — настройка → модуль → маршрут → ошибки → проверка |
| `.claude/agents/style-reviewer.md` | субагент: сверяет diff с `CLAUDE.md`, запускает проверки, код не правит |
| `ruff.toml` | линтер под стиль проекта: код недели 7 проходит чисто |
| `experiment/rules/v1/` | первая версия всех правил — для повторной генерации |

### Запуск

```
.\experiment\generate.ps1 qwen-v1 -Rules v1      # правила v1
.\experiment\generate.ps1 qwen-v2                # текущие правила (v2)
.\experiment\generate.ps1 opus-v2 -Provider claude   # Claude Code по подписке
```

Ключ `DASHSCOPE_API_KEY` — из переменной окружения или `.env`. Переменные Qwen скрипт ставит только на время
прогона: обычный Claude Code в том же окне и в других проектах работает по подписке.

### Как проверить задание

- **Файл правил v2** — `CLAUDE.md`, скилл, субагент и конфиг в корне; v1 — `experiment/rules/v1/`.
- **Диффы двух генераций** — `experiment/qwen-v1/changes.diff` и `experiment/qwen-v2/changes.diff`; у каждой —
  `result.md` (ответ, время, ходы, токены, инструменты) и `checks.txt` (линтер, импорт, ответы эндпоинта).
- **Что повлияло на качество** — «Находки».

Изменения правил v1 → v2 — по разбору генерации opus-v1:
- «Соглашения»: эндпоинт без потока — 400 на неверный вход, 503 без Ollama; ошибки валидации по-русски через
  один обработчик `RequestValidationError`; «сначала найди готовое» — opus-v1 завёл `find` рядом с `search`;
- «Проверка»: команда — отдельным вызовом, пути относительные через `/`; рецепт вызова эндпоинта без Ollama —
  `TestClient` без lifespan, векторы заглушкой, кэш во временной папке;
- «Субагенты и скиллы»: `style-reviewer` — только после нового модуля или правок больше чем в трёх файлах;
- скилл — коды ошибок и проверка через `TestClient`; конфиг — разрешения под Bash.

### Находки

- **Рецепт с готовой командой выполняется, правило в списке — нет.** Qwen с v2 скопировал заглушку из
  «Проверки» и вызвал свой эндпоинт. Но 503 и обработчик валидации из «Соглашений» не сделал: английский 422
  увидел в своём же тесте и записал в отчёт как норму. Правило, которое нужно применить, лучше давать
  критерием готовности в скилле, а не строкой среди двадцати.
- **Больше всего на процесс повлиял раздел «Проверка».** v1 склеивала команды через `;`, разрешения были
  записаны с `\` для PowerShell — в `claude -p` спросить некого, и проверки падали: у Opus 5 отказов, у Qwen 8.
  Opus отдал проверки субагенту, Qwen — сдал код с ошибкой линтера. С «отдельным вызовом, пути через `/`» —
  2 ошибки, обе от запуска сервера, о котором не просили.
- **Субагент на мелкую правку — лишние минуты.** Правило «`style-reviewer` — только для крупных правок»
  сократило Qwen со 180 до 82 с без потери проверок.
- **Глобальный конфиг тоже влияет.** Qwen с v1 вместо скилла проекта взял `code-review` из глобальных плагинов.
  Около 400 тыс. входных токенов почти не зависят от правил: это системный промпт Claude Code и плагины.
- **Opus угадывает то, чего нет в правилах:** 503 без Ollama, 400 по-русски на пустой `q`. Qwen без явного
  правила делает как в типовом FastAPI. Поэтому правила проверяли на Qwen.
- **Настройки проекта в незнакомой папке не действуют**: «workspace has not been trusted» — разрешения из
  `.claude/settings.json` скрипт передаёт флагом `--allowedTools`.
- **DashScope не кэширует промпт** в Anthropic-режиме (`cache_read_input_tokens: 0`): каждый ход заново
  оплачивает весь контекст.

## День 37. Профили агентного режима: Bug Fix, Research, «Перед коммитом»

Три профиля Claude Code: системный промпт, набор инструментов, что профиль должен и не должен делать, формат
ответа. Профиль включается на всю сессию — `claude --agent bug-fix`. Каждый проверен на реальной задаче одним
промптом без человека на `qwen3.5-122b-a10b` (DashScope); не сработал — профиль доработан и прогнан снова.

### Как работает

```
.claude/agents/<профиль>.md          frontmatter: имя, описание, инструменты · тело — системный промпт
        │
claude --agent <профиль>             промпт профиля заменяет системный промпт Claude Code, инструменты — только
        │                              из списка; CLAUDE.md проекта и глобальный остаются в контексте
experiment/generate.ps1 <имя> -Agent <профиль> [-Clone]
  ├─ копия проекта в %TEMP%\claude-rules\<имя>; -Clone — с историей git и незакоммиченными правками
  ├─ claude -p --agent <профиль> < experiment/tasks/<профиль>.md
  └─ experiment\<имя>\: профиль, log.jsonl, changes.diff, checks.txt, result.md
        checks.txt — ruff, импорт, файлы, которые изменил агент, и проверка задачи experiment/tasks/<профиль>.py
```

### Профили

- **`bug-fix`** — Read, Grep, Glob, Edit, Bash; без Write — временных файлов не остаётся. Должен: воспроизвести баг
  до правки и той же командой после, найти строку-причину и все задетые места, прогнать ruff и импорт. Не должен:
  чинить симптом (`try/except`), трогать лишнее, объявлять «исправлено» без повторного воспроизведения, коммитить.
  Ответ: что нашёл → что починил → что проверил (таблица) → что не проверено.
- **`research`** — Read, Grep, Glob, Bash; без Edit и Write — менять файлы нечем. Должен: первым вызовом — карта
  входов, каждое утверждение — `файл:строка`, прочитанная в этой сессии, отсутствие — прямо («авторизации нет»).
  Не должен: менять файлы, утверждать без места в коде, чинить. Ответ: коротко → файлы → связи (схема) → выводы →
  где искал.
- **`commit-check`** — Read, Grep, Glob, Bash. Должен: проверить всё, что уйдёт в `git add -A`, — секреты, адреса и
  почту, лишние файлы, следы ИИ, ruff и импорт. Не должен: менять файлы и индекс, показывать секрет целиком, писать
  «чисто» без поиска. Ответ: вердикт → что войдёт → таблица проверок → что исправить → команда коммита.

Общее: какие команды проходят без подтверждения (в `claude -p` спросить некого); у Bug Fix и Research ещё —
настройки через `os.environ` внутри `python -c` и вывод Python в UTF-8.

### Запуск

```
claude --agent research                                    # сессия в профиле; так же bug-fix и commit-check
.\experiment\generate.ps1 bug-fix-v1 -Agent bug-fix -Model qwen3.5-122b-a10b
.\experiment\generate.ps1 research-v3 -Agent research -Model qwen3.5-122b-a10b
.\experiment\generate.ps1 commit-check-v1 -Agent commit-check -Clone -Model qwen3.5-122b-a10b
```

В обычной сессии профиль работает и как субагент: «проверь перед коммитом» → `commit-check`.

### Задачи

- **Bug Fix** — настоящий баг: с `HOST=0.0.0.0` (открыть ассистента с другого устройства) в шапке ветка «?»,
  `/help` падает на шаге MCP: «Server returned an error response». Профиль получил только симптом —
  `experiment/tasks/bug-fix.md`. Причина — `app/config.py`: адреса MCP собирались из `HOST`, к `0.0.0.0` подключиться
  нельзя, запрос уходит в системный прокси и получает 503. Проверка стенда — `experiment/tasks/bug-fix.py`: сервер с
  `HOST=0.0.0.0` и с `127.0.0.1`, все три MCP-сервера.
- **Research** — «Как у нас устроена авторизация? Кто может пользоваться ассистентом и его MCP-серверами и что
  через них можно сделать?». Верный ответ: авторизации нет, защита — только `HOST=127.0.0.1`.
- **«Перед коммитом»** — настоящий коммит дня 37.

### Как проверить задание

- **Профили** — `.claude/agents/bug-fix.md`, `research.md`, `commit-check.md`.
- **Успешные прогоны** — `experiment/bug-fix-v1/`, `research-v3/`, `commit-check-v1/`: `result.md` (ответ, время,

- **Что доработано после первой попытки** — неудачные `experiment/research-v1/`, `research-v2/` и список ниже.
- **Фикс бага** — `app/config.py`: из `experiment/bug-fix-v1/changes.diff`, исправлена опечатка в комментарии.

## День 38. Testing: тесты кода и smoke-сценарии через Playwright MCP

Профиль Claude Code `qa` проводит два уровня тестирования. Первый — unit-тесты модулей `app/`: агент сам находит непокрытые
модули, пишет тесты и прогоняет их. Второй — smoke-сценарии UI: агент сам проходит их в браузере через Playwright MCP,
снимает скриншот на каждом шаге и при падении называет место в коде. Оба уровня собираются в один отчёт. Профиль встроен в
flow: его зовут после PR и после новой фичи. Прогоны шли без человека на `qwen3.5-122b-a10b`.

### Как работает

```
claude --agent qa   «напиши тесты» | «проверь PR» | «задеплоил новую фичу — обнови smoke-сценарии и прогони всё заново»
  ① что изменилось — git status / diff по app/ и static/
  ② уровень 1 — модули без tests/test_<модуль>.py → значения для assert — пробой командой → тесты
       tests/run.py: Ollama, data/ и ML-проект отрезаны — тест без заглушки падает, а не портит кэш
```

- **Запрет механизмом надёжнее запрета словами — снова.** В v1 при правиле «Ollama не вызывается никогда» тест полез в
  Ollama и записал кэш векторов в `data/` — в проекте он затёр бы настоящий. После `tests/run.py`, который отрезает Ollama,

- **Отчёт агента о себе проверять нужно.** «Первый запуск» после трёх запусков, «всё прошло» с пропущенным сценарием,
  выдуманная ветка. Помогает то, что проверяемо командой: список сценариев, ветка, независимый прогон тестов стендом.
- **Правило в середине фразы теряется.** Формулировка «тесты на изменённые функции, потом прогон всех» превратилась у агента в

- **Playwright MCP 0.0.83 экономит токены сам.** Снимок страницы сохраняется в файл, в ответе — только ссылка. Клик идёт по

  результаты, которые остаются на экране.
- **Smoke на Qwen дорогой.** 70+ ходов — 1,9–2,3 млн токенов: DashScope не кэширует, и каждый шаг в браузере заново оплачивает

- **Фоновый сервер даёт второй `result` в логе.** В конце Claude Code останавливает сервер и будит агента уведомлением. Стенд

## День 39. Local Boost: локальная модель как код-ассистент в IDE

Continue в PyCharm работает на моделях Ollama. Чат, правка и агент — на qwen3-coder 30B или qwen3.5 4B, автокомплит — на
qwen2.5-coder 1.5B. Правила проекта идут в системный промпт. Те же задачи, что у облачного ассистента в днях 36–37, прогнаны
тем же стендом: Claude Code работает на локальной модели через Anthropic-совместимый API Ollama. Модель в прогонах меняется,
правила, код и проверки — те же.

### Как работает

```
PyCharm + Continue 1.0.67 — .continue/agents/local.yaml, всё через Ollama на 127.0.0.1, без интернета
  ├─ чат, правка, агент  qwen3-coder:30b-gpu36 (36 из 49 слоёв — на Radeon 780M) или qwen3.5:4b без размышлений
  │     системный промпт   .continue/rules/project.md — CLAUDE.md без раздела о субагентах Claude Code
  │     что видит модель   текущий файл, открытые вкладки, @file, @code, дерево, diff, терминал, ошибки;
  │                        не видит .gitignore и .continueignore (прогоны experiment/*/)
  └─ автокомплит         qwen2.5-coder:1.5b-base: 1024 токена кода вокруг курсора, после паузы 300 мс

те же задачи, что у облака
experiment/generate.ps1 <имя> -Provider ollama -Model <модель> [-Context N -Gpu N] -Rules <облачный прогон> -Ref e9565b9
  ├─ вариант модели в Ollama: num_ctx — Anthropic API контекст не передаёт; num_gpu — сколько слоёв на видеокарту
  ├─ Claude Code → http://127.0.0.1:11434; правила облачного прогона, код — из коммита дня 36, баг дня 37 на месте
  └─ experiment\<имя>\: result.md, changes.diff, checks.txt — как у облачных прогонов
experiment/bench.py <модель> [контекст] [fim] [gpu=N] — промпт и генерация, ток/с; память под модель
```

| Настройка | Значение | Почему |
|---|---|---|
| Правила | `.continue/rules/project.md`, ~3 тыс. токенов | Continue добавляет их к системному промпту чата, правки и агента; в автокомплит — нет |
| Контекст чата | 32 тыс. токенов | правила и несколько файлов; 30b с ним — 20,6 ГБ, с 48 тыс. — 22,2 ГБ и меньше слоёв на видеокарте |
| Генерация | temperature 0.2, top_p 0.9, ответ до 4096 токенов | код по правилам, а не творчество; у моделей по умолчанию 0.7/0.8 (qwen3-coder) и 1.0/0.95 (qwen3.5) |
| qwen3.5 4B | `think: false` | размышления в чате дольше самого ответа |
| Автокомплит | 1024 токена, пауза 300 мс | подсказка — за 1,2 с |

**Для чего хватает локальной.** Хватает для автокомплита, вопросов по открытому файлу или функции, коротких правок
выделенного кода, кода без интернета или под NDA. Лучшая связка на этом железе:

- автокомплит — qwen2.5-coder:1.5b-base, подсказка за 1,2 с.

**Облако незаменимо** для агентного режима (поиск причины бага командами, многошаговые правки), длинного контекста и
точного следования правилам проекта.

### Находки

- **Встроенная видеокарта втрое ускоряет чтение промпта, но 30b в неё целиком не помещается.** По умолчанию Ollama её
  отключает, включает её `OLLAMA_IGPU_ENABLE=1`: у 4b промпт ускорился со 130 до 429 ток/с. Все 17,5 ГБ весов 30b llama-server
  в общую видеопамять не загрузил: упал с `0xe06d7363` без сообщения в логе, а сам Ollama слои не урезает. 36 слоёв (12,8 ГБ)
  работают. Число слоёв задаёт `num_gpu` в Modelfile.
- **На длинном контексте важнее устройство модели, чем её размер.** У qwen3.5 полное внимание только в 8 слоях из 32:
  на 27 тыс. токенов генерация держит 17 ток/с. У qwen3-coder его все 48 слоёв, и часть считает процессор — 2,2 ток/с.
  Отсюда 27 минут на фичу при 22 ходах.
- **Кэш начала промпта спасает агентный режим.** Каждый ход Claude Code шлёт 14–27 тыс. токенов. Ollama дочитывает только
  новые — от десятков до 3 тыс. Без этого 30b тратила бы минуты на каждый ход.
- **В агентном режиме локальные модели не ищут, а заполняют форму ответа.** У профиля bug-fix форма «что нашёл → что
  починил → что проверил». Обе модели сразу заполнили её выдуманными строками кода и проверками. Облачный qwen3.5-122b с тем же
  профилем сделал 16 вызовов. Это тот же провал, что у Research v1–v2 в дне 37.
- **Claude Code сам не задаёт temperature и контекст, а размышления (`thinking: adaptive`) просит.** Поэтому в прогонах стенда
  действуют параметры модели по умолчанию, и qwen3.5 размышляет и локально. Контекст задаёт вариант модели с `num_ctx`, иначе Ollama
  берёт 4–32 тыс. токенов в зависимости от видеопамяти. Это проверено заглушкой на месте API.
- **Правила Continue читает из `.continue/rules/`.** `uses: file://` в конфиге принимает только абсолютный путь, поэтому правила
  — копия `CLAUDE.md`.
- **В PyCharm Community Continue из Marketplace не поставить.** Плагин помечен только для платных IDE, хотя зависит лишь от
  платформы и Terminal: из zip встаёт и работает. Конфиг в списке Continue называется по имени файла (`local.yaml`), а не по полю
  `name`.
- **На русской Windows Continue в PyCharm 2024.1 портит кириллицу.** Правила, файлы и ответ модели превращаются в «пїЅпїЅ» и
  «РЇ РІРёР¶Сѓ». Плагин обменивается со своим процессом в кодировке по умолчанию, а Java 17 в PyCharm 2024.1 берёт её из системы
  (cp1251). Лечится строкой `-Dfile.encoding=UTF-8` в VM options; PyCharm надо закрыть целиком, а не только окно.

## День 40. Execution Loop: кто дольше продержится без паузы

Пул из 17 задач в текстовом трекере: баги, мелкие фичи, рефакторинг, недостающие тесты, документация, вопросы о коде; у каждой
задачи — «Готово, когда». Claude Code в режиме execution loop сам берёт первую открытую задачу, выбирает профиль, выполняет её,
проверяет и коммитит. Стенд запускает его снова с тем же промптом на следующую задачу и проверяет каждую сам, человек не
вмешивается. Облачных прогонов два, оба на `qwen3.5-122b-a10b` в DashScope: v1, затем разбор сбоев, правила v2 и прогон v2. Тот же
пул прогнан на локальной `qwen3-coder:30b`.

### Как работает

```
experiment/loop.py <прогон> [--rules <прогон>/rules] [--provider ollama --model …]
  копия проекта %TEMP%\claude-rules\<прогон> + TASKS.md из experiment/loop/tasks.md; ML-проект — тоже копия
  пока в TASKS.md есть «Статус: открыта»:
    claude -p < prompt.md                 тот же промпт на каждую задачу, контекст — новый
      ① первая открытая задача
      ② профиль: баг → bug-fix · вопрос → research · тесты → qa · фича, рефакторинг, документация → сам (+ new-endpoint)
      ③ «Готово, когда» — командой с assert → ruff, импорт, tests/run.py
      ④ статус в TASKS.md → git commit «L-NN: …»
    незакоммиченное — откат; не закрыл задачу — «не сделана» отметкой цикла; дольше 15 мин — зависла
    experiment/loop/check.py L-NN         своя проверка критерия: TestClient, сервер, порча кода для задач на тесты
    тесты, ruff, импорт до и после        новых падений быть не должно
  experiment\<прогон>\log.md             задача → профиль → результат → время; подряд без вмешательства, с первого раза
```

- **Трекер — файл `TASKS.md`.** Статус задачи — строка под заголовком. Агент меняет её сам и коммитит вместе с работой.
- **Профиля в задаче нет** — агент выбирает его по смыслу. Какой профиль ждали, знает только стенд.
- **Проверяет стенд, а не агент.** `check.py` вызывает код так, как написано в «Готово, когда». У задач на тесты он ещё и
  ломает функцию заменой строки и ждёт, что тесты упадут. Все 17 проверок отклоняют исходный код и принимают эталонные решения.
- **Сбой** — агент не закрыл задачу или не закоммитил её, проверка не прошла, тесты или ruff стали хуже, задача шла дольше
  15 минут.
- **Только правила проекта.** `--setting-sources project,local` не пускает в цикл глобальный `CLAUDE.md` и плагины. Самопланирование
  агента (`ScheduleWakeup`, `Cron*`, `Workflow`) выключено: цикл ведёт стенд.

### Запуск

```
.venv/Scripts/python.exe experiment/loop.py loop-v2 --model qwen3.5-122b-a10b          # текущие правила
.venv/Scripts/python.exe experiment/loop.py loop-v1b --rules experiment/loop-v1/rules   # правила v1
.venv/Scripts/python.exe experiment/loop.py loop-local --provider ollama --model qwen3-coder:30b --context 49152 --gpu 32 --minutes 30 --stop-on-fail
.venv/Scripts/python.exe experiment/loop.py loop-v1 --report                            # пересобрать log.md
```

Ключ `DASHSCOPE_API_KEY` берётся так же, как в днях 36–39. Для локального прогона нужен запущенный Ollama.

### Как проверить задание

- **Пул задач** — `experiment/loop/tasks.md`: 5 багов, 3 фичи, 2 рефакторинга, 3 задачи на тесты, 2 на документацию,
  2 вопроса. Чем проверяется каждая — `experiment/loop/check.py`.
- **Лог выполнения** (задача → профиль → результат → время) — `log.md` в `experiment/loop-v1/`, `loop-v2/` и `loop-local/`.
  Там же трекер после прогона (`TASKS.md`), коммиты агента (`commits.txt`) и логи агента (`L-NN.jsonl`).
- **«Сколько подряд без паузы» в двух прогонах** — первая строка каждого `log.md` и таблица ниже.
- **Что доработано между прогонами** — правила v1 лежат в `experiment/loop-v1/rules/`, v2 — в корне проекта:
  `experiment/loop/prompt.md`, `.claude/agents/research.md`, `.claude/skills/new-endpoint/SKILL.md`.
- **Облако против локальной модели** — таблица ниже.

Что доработано между v1 и v2 — только то, на чём сломался v1:
- **Промпт цикла.** Перед «сделана» — одна команда `python -c` с `assert` на каждый пункт «Готово, когда» дословно: код, текст, имя
  параметра, каждая функция, каждый случай. Профиль — это вызов субагента; пока субагент работает, ту же задачу самому не делать.
- **Профиль `research`.** В `description` стояло «…по кодовой базе: сам находит…». Двоеточие с пробелом ломает YAML, и Claude
  Code 2.1.310 не загружал профиль: «Agent type 'research' not found».
- **Скилл `new-endpoint`.** `FileNotFoundError` (нет документации) — тоже 503. Проверять пустой `PROJECT_DIR` и `llm.embed`, который
  бросает `LLMError`. Если нужная функция модуля уже есть — вызвать её, а не заводить вторую.

### Находки

- **Ломалась не логика, а проверка себя.** Во всех трёх сбоях v1 агент написал «сделана», проверив критерий частично: фраза без
  имени параметра, 12 функций из 13, все случаи, кроме «нет документации». После правила «assert на каждый пункт» v2 прошёл весь
  пул подряд, но токенов ушло на 31 % больше. Вывод тот же, что в днях 36–38: работает проверка командой, а не правило в списке.
  v2 доработан под сбои v1 на том же пуле — на новых задачах счёт может быть другим.
- **Цикл нашёл дефект профиля.** Профиль `research` не загружался, и увидеть это можно только в логе. Агент получал «not found»,
  молча уходил в `general-purpose`, а пока тот работал, искал ответ сам — одна работа делалась дважды. Задачи при этом прошли.
- **Самопланирование ломает внешний цикл.** В первом заходе (`experiment/loop-v0/`) агент запустил `bug-fix` в фоне и, чтобы его
  дождаться, вызвал `ScheduleWakeup` с промптом цикла. Через минуту тот же контекст взял L-02 — сам, без `qa`, мимо проверки стенда,
  за 774 тыс. токенов. Стенд исправлен: самопланирование выключено, а если агент закроет несколько задач за заход, каждая
  проверяется на своём коммите в отдельной рабочей папке.
- **Профиль выбран верно в 14–15 задачах из 17.** Задачи на тесты агент дважды писал сам, хотя в ответе называл профиль `qa`:
  назвать профиль — ещё не вызвать его. К сбою ни один неверный выбор не привёл.
- **Задача в облаке — 1–7 минут и 0,2–1,8 млн токенов.** Дороже всего задачи на тесты и баги с воспроизведением (L-09, L-12,
  L-14): DashScope не кэширует промпт, каждый ход оплачивает весь контекст, а субагент — ещё и свой.
- **Локальная модель не дошла до задачи.** Рабочая папка указана в системном промпте, но qwen3-coder:30b трижды читала трекер в
  домашней папке и повторяла тот же отклонённый вызов. Прочитав его через `cat`, она ушла в повтор токенов. Итог — 11 минут и
  8 ходов. В дне 39 эта модель сделала одну фичу за 27 минут, но для цикла с трекером и субагентами её не хватает ни по скорости,
  ни по устойчивости.
- **`modelUsage` в логе накопительный за заход.** Сумма по событиям `result` завысила токены в 1,6 раза: 1,79 млн вместо 1,11.
  Стенд берёт последнее значение.
